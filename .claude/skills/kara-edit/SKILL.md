# แก้ PU KARAOKE แบบตรงจุด

โปรเจกต์ใหญ่ (server.py ~5.1k บรรทัด, studio.html ~2.4k, remote.html ~1.2k, player.html ~1.1k, scripts ~5k)
**อย่าไล่อ่านทั้งไฟล์** — `MAP.md` (โฟลเดอร์เดียวกับไฟล์นี้, ~90 หัวข้อ) บอกแล้วว่าแต่ละเรื่องอยู่ไฟล์ไหน ตรงไหน
`MAP.md` เองก็ใหญ่ (~700 บรรทัด) — **อย่าเปิดอ่านทั้งไฟล์** ให้ค้นผ่านตัวช่วยนี้ ซึ่งแปลงเป็นเลขบรรทัดปัจจุบันให้ด้วย
(อ้างไฟล์จากราก repo ที่กำลังทำงาน — worktree ก็ได้):

    python3 "${CLAUDE_SKILL_DIR}/kmap.py" <status|find|topics|outline|check> ...

## ขั้นตอน (ทำตามลำดับทุกครั้ง)

0. **เช็กว่า worktree ไม่เก่า** — `kmap.py status`
   - ขึ้น ⚠ เก่ากว่าโฟลเดอร์หลัก → รัน `git merge --ff-only <branch>` ตามที่มันบอก ก่อนอ่าน/แก้อะไร
     (แอปสร้าง worktree จาก main ที่เก่า — โค้ดที่เซิร์ฟเวอร์จริงใช้อยู่คือ branch ของโฟลเดอร์หลัก)
1. **หาจุด** — `kmap.py find <คำสำคัญ 1–3 คำ>` ไทยหรืออังกฤษ เช่น `find ช่องค้นหา`, `find คิว รีโมท`, `find ป้าย ตรวจเวลา`
   - ได้หัวข้อ + `ไฟล์:บรรทัด` ของทุก anchor + ข้อควรระวัง (`!`) — อ่านข้อควรระวังทุกครั้ง
   - เรื่องเดียวมักกินหลายไฟล์ (CSS + HTML + JS ในหน้าเดียว, หน้าเว็บ + route ใน server.py) — หัวข้อจะบอกครบ
   - ไม่เจอ → ลองคำอื่น → `kmap.py topics` (รายชื่อหัวข้อทั้งหมด) → `kmap.py outline <ไฟล์> [คำกรอง]`
2. **อ่านเฉพาะช่วง** — Read ด้วย offset/limit รอบบรรทัดที่ได้ (ปกติ 40–80 บรรทัดต่อจุด)
   - ห้ามอ่านทั้งไฟล์ (ยกเว้นไฟล์สั้นกว่า 200 บรรทัด) และไม่ต้องเปิด Explore agent ถ้าแผนที่ชี้ได้แล้ว
   - ต้องตามไปดูฟังก์ชัน/ตัวแปร/CSS ที่เกี่ยว → `grep -n` ชื่อนั้นก่อน แล้วอ่านเฉพาะช่วง
   - ไม่ต้องอ่าน transcript, เนื้อเพลงจริง หรือ `songs/` เพื่อหาโค้ด
3. **แก้เฉพาะจุดนั้น** ตามสไตล์รอบข้าง (คอมเมนต์ภาษาไทย ความหนาแน่นคอมเมนต์เท่าเดิม)
4. **อัปเดตแผนที่** ถ้าเพิ่ม เปลี่ยนชื่อ ลบ หรือย้าย ฟังก์ชัน / section / route / ฟีเจอร์
   - แก้ `MAP.md` (เพิ่มหรือแก้ anchor, เพิ่มหัวข้อ, เพิ่มคำค้น) แล้วรัน `kmap.py check` ต้อง ERROR 0
   - check บอก "ยังไม่มีในแผนที่" = route / section / ไฟล์ใหม่ที่ควรมีหัวข้อ
   - commit `MAP.md` ไปพร้อมโค้ดที่แก้

## รูปแบบหัวข้อใน MAP.md

    ## กลุ่ม (ไฟล์หลัก)
    ### หัวข้อภาษาไทย
    คำค้น: คำที่ผู้ใช้น่าจะพูด, english words
    - `ไฟล์` `anchor1` `anchor2` — โน้ตสั้น
    ! ข้อควรระวัง

anchor = ข้อความที่อยู่ในบรรทัดเดียวของไฟล์ และไม่ซ้ำในไฟล์นั้น (เช่น `function search(`, `@app.get("/r"`, `// ===== 7b.`, ` .search{`)
ห้ามใส่เลขบรรทัดในแผนที่ (เปลี่ยนทุกครั้งที่แก้) และห้ามมี backtick ใน anchor

## กฎของโปรเจกต์นี้

- เซิร์ฟเวอร์จริง (`python -u server.py` พอร์ต 8080) ผู้ใช้เปิดเองและใช้อยู่ — **ห้ามปิด/รีสตาร์ท**; แก้ server.py แล้วบอกให้ผู้ใช้รีสตาร์ทเอง
- หน้า html อ่านจากดิสก์ทุก request → แก้แล้วแค่รีโหลดหน้า · `scripts/*` ถูกเรียกเป็น subprocess → มีผลกับเซิร์ฟเวอร์จริงทันที ต้องคง CLI/JSON เดิมไว้
- ห้ามแก้เนื้อเพลงจริง (`songs/yt/**/lyrics*.json`, `lyrics-in/*.json` ที่ผู้ใช้แก้เองใน Studio)
- ทดสอบบนคลังจำลอง TEST* + เซิร์ฟเวอร์ทดสอบพอร์ตอื่น + headless Chrome — รายละเอียดใน memory `live-server-and-testing`
- ฟีเจอร์ใหม่ที่แสดงบนจอทีวีต้องมีปุ่มเปิด/ปิด (tv.json/TV_SCHEMA + Studio 📺; ถ้าแขกอยากสลับเองก็ใส่ในรีโมท ⚙️) ปิดแล้วต้องเหมือนเดิม
- commit / ติดตั้งเมื่อผู้ใช้อนุญาตเท่านั้น: commit ใน worktree แล้ว `git -C <โฟลเดอร์หลัก> merge --ff-only <branch ของ worktree>` (ไม่แตะไฟล์ที่ผู้ใช้ยังไม่ commit เช่น tv.json, ไม่ push)
